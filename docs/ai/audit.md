| Repository Release gate | Clean build with zero warnings and errors. Unit/integration: 264 passed, zero failed, skipped or blocked. Browser suite: 47 passed, five optional skips, zero failed or blocked. |

| Dashboard Starter regression | 31 Chromium cases passed, zero failures, skips or blocked cases. Development and Production each passed 11 baseline and three input cases. Customized identity and two logo/configuration cases passed. CSV and XLSX contained the same ten expected IDs in both environments. |

## Reproduce

From the repository root, with Python 3, the .NET 10 SDK and access to NuGet.org:

```sh
python3 docs/ai/validate.py
```

The script prints its new temporary directory. It checks every source component against its table, copies the fenced examples from Markdown into the consumer, applies the four setup sections to the actual host, builds, requests each example route, installs the public Starter in an isolated CLI home, and builds the generated app. The showcase provider fixture is compiled as consumer application code. Keep the printed directory to inspect generated sources, restore manifests and render logs.

Run the regression gate after installing the pinned Chromium build as described in the [repository README](../../README.md). The negative checks use the same directory as the original TRX files.

```sh
export CHAMPUI_EVIDENCE_DIR="$(mktemp -d)"
bash verify_fixes.sh
python3 tests/verify_ci_gates.py "$CHAMPUI_EVIDENCE_DIR"
```

The [Starter suite](../../tests/ChampUI.TemplateTests/README.md) additionally exercises generated apps in Development and published Production. To include typing checks set CHAMPUI_INPUT_AUDIT to the absolute tests/UiTextField.Audit directory. Its Development path verifies the approved local Core artifact and its Production path verifies the public signed package. The documentation gate uses public restore for both consumers.

## Corrections and boundaries

The root installation example previously pinned Core 0.3.1. The template README described installing from a local build and waiting for Core publication. Updated instructions use both published IDs and versions. A read-through of the inline editing example identified a cached local row collection; the recipe supplies a new collection after saving the edit copy. The UiTextField example passes a C# variable explicitly to the string Value parameter. The public compiler reported no incorrect API signatures in the final examples.

The five existing optional browser skips cover three diagnostics plus Firefox and WebKit. The 52 documentation routes verify construction and prerendering; individual interactions are covered by the existing product suites where applicable. Manual assistive-technology tests and end-user testing of the five new recipes were outside this documentation run. Advanced scheduling, POS and persistence are application responsibilities. The README corrections apply to this source branch; published archives retain their original contents.
